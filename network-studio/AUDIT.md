# Content and demonstration audit

Reviewed 20 September 2026. This is a new application in `network-studio`, scaffolded separately from the previous Next.js application. The subject remains the supplied Mongolian textbook section 2.2; the prose and learning sequence were written again.

## Source inspection

The supplied PDF has **17 PDF pages**, corresponding to printed pages **54–70**. The networking lesson is primarily printed pages 54–66; the later pages contain the chapter summary and exercises. The original is preserved in `public/source.pdf`.

`pdftotext -layout` produced no text for PDF pages **1, 2, 4, and 12** (printed pages **54, 55, 57, and 65**). Those pages were rendered and visually read rather than treated as blank. The temporary `/tmp/network-studio-source.txt` extraction retains page boundaries and includes explicitly labeled, manually written summaries for the image-only pages. It is not a claim of complete OCR transcription.

## Problems in the previous application

These findings distinguish actual defects from simplified or weak demonstrations. The previous prose already contained several correct limitations; those should not be described as previous factual errors.

| Previous evidence                                                                                                                 | Issue                                                                                                                                                                                          | New treatment and learning purpose                                                                                                                                                                                                                                                                                                                                |
| --------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `app/components/packet-lab.tsx` creates exactly four chunks for arbitrary editable text.                                          | A one-, two-, or three-character message produces empty “packets”, displayed as ∅. These are artifacts of the UI, not required network packets.                                                | Use a meaningful fixed four-part message. No empty payload pieces. The learner can follow an intact message before and after transfer.                                                                                                                                                                                                                            |
| Packet loss requires clicking “Дутууг дахин илгээх”. There is no visible ACK returning to the sender.                             | Manual intervention demonstrates a person retrying, but does not demonstrate the automatic recovery promised by the TCP explanation.                                                           | The model sends a visible acknowledgement separately from data and automatically retries the intentionally lost piece after a modeled timeout. Explicitly state that real TCP numbers bytes and uses more mechanisms. [TCP](https://www.rfc-editor.org/rfc/rfc9293.html)                                                                                          |
| Packets are offset in identical linear lanes with the same transit duration.                                                      | Reassembly is mentioned in prose, but out-of-order arrival is not observable.                                                                                                                  | Follow an explicit out-of-order arrival scenario and distinguish arrival order from the correctly reconstructed application message. A later piece arriving cannot fill an earlier gap. [TCP](https://www.rfc-editor.org/rfc/rfc9293.html)                                                                                                                        |
| Packet animation duration is `1800 + latency * 4 + 2400 / bandwidth`; the displayed estimate is `8 / bandwidth + latency / 1000`. | The animation and numerical calculation use unrelated models. The previous disclaimer made the animation illustrative, but the simultaneous sliders still suggested a quantitative connection. | Separate packet reliability from transfer-time arithmetic. The speed lesson exposes serialization and one-way propagation as separate quantities, derives its result from `8 × MB / Mbps + propagationMs / 1000`, and labels playback as illustrative. [Delay components](https://www.cisco.com/c/en/us/support/docs/voice/voice-quality/5125-delay-details.html) |
| Both selected domains return the same `192.0.2.10`; cache is a checkbox with no lookup history.                                   | Multiple domains sharing an IP is valid. The weakness is pedagogical: changing domain has no observable lookup consequence, and the cache is preasserted rather than learned.                  | Give the two example domains distinct documentation IPs, show a first lookup and a repeat lookup, and key stored results by domain. This makes the effect of reuse visible without suggesting that every domain must have a unique IP. [DNS](https://www.rfc-editor.org/rfc/rfc1034.html)                                                                         |
| Intro labels list device → DNS → router → server.                                                                                 | This can be read as one data path, even though DNS lookup and the web request are different exchanges.                                                                                         | Introduce device ↔ router ↔ server first. Explain DNS in a separate lesson and state that website data does not have to pass through a DNS server. [DNS](https://www.rfc-editor.org/rfc/rfc1034.html)                                                                                                                                                             |
| Topology uses breadth-first search over equally weighted links.                                                                   | This algorithm is correct for the model. The previous prose correctly said “fewest hops”, but a visual shortest route can still imply fastest real-world route.                                | Keep the useful intervention but label equal link costs. Display no-route outcomes and name the limitation: actual protocols use metrics and policies, and recovery takes time. [OSPF](https://www.rfc-editor.org/rfc/rfc2328.html)                                                                                                                               |
| Final exercise only asks the learner to enable every link in a fixed chain.                                                       | Successful clicking does not strongly establish a causal explanation or transfer to a new case.                                                                                                | End with predictions, explicit answer feedback, and reasons. Ask learners to compare what changed with what stayed constant. This is a teaching-design judgment, not a standards claim.                                                                                                                                                                           |

## Corrections to the textbook baseline

| Printed page | Claim requiring correction or qualification                                                                                | Treatment                                                                                                                                                                                                                                                                                                                                    |
| ------------ | -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 55           | LAN speed is given as 10–1000 Mbps.                                                                                        | Do not teach this as a definition or current maximum. Classify by setting and use; omit universal rate and distance limits. [Cisco LAN](https://www.cisco.com/site/us/en/learn/topics/networking/what-is-a-lan-local-area-network.html)                                                                                                      |
| 56           | Failure of a host implies the network automatically takes another channel.                                                 | Recovery requires an available alternate path and functioning mechanisms. The graph can be disconnected completely; the model reports failure rather than inventing a path. [OSPF](https://www.rfc-editor.org/rfc/rfc2328.html)                                                                                                              |
| 58           | UTP wording implies electromagnetic effects cannot change its signal.                                                      | Twisting and differential signaling reduce interference; they do not make copper immune. Optical transmission has different impairments, so “immune to electromagnetic interference” is not “immune to every error”. [Physical infrastructure](https://www.cisco.com/c/en/us/td/docs/sanity/suman/CPwE-Physical-Infrastructure_Feb2023.html) |
| 58           | Router software is generically called IOS.                                                                                 | IOS is not the universal operating system of routers. The presentation describes processing, memory, interfaces, and forwarding roles without assigning every product one vendor's OS. [Router functions](https://www.cisco.com/site/us/en/learn/topics/small-business/what-is-a-router.html)                                                |
| 59           | Fiber is described as necessarily one-way and therefore always used in pairs.                                              | Many designs use a pair, but single-fiber bidirectional links also exist. Do not repeat the universal rule. [Cisco bidirectional optics](https://www.cisco.com/c/en/us/products/collateral/interfaces-modules/gigabit-ethernet-gbic-sfp-modules/datasheet-c78-366584.html)                                                                   |
| 62           | Wi-Fi can appear to be an alternative to needing an Internet upstream.                                                     | Wi-Fi provides a local wireless link. A device may be associated with Wi-Fi while Internet access is unavailable. [Cisco LAN](https://www.cisco.com/site/us/en/learn/topics/networking/what-is-a-lan-local-area-network.html)                                                                                                                |
| 64           | Class A/B/C is presented as the current addressing scheme; the explanation of the host part of `192.168.0.1` is incorrect. | Teach prefix lengths such as /24. The network/host division depends on the prefix, not simply the first octet. IPv4 is 32 bits; IPv6 is 128. [CIDR](https://www.rfc-editor.org/rfc/rfc4632.html), [IPv6](https://www.rfc-editor.org/rfc/rfc8200.html)                                                                                        |
| 64           | A dynamic address is described as changing on every connection.                                                            | Dynamic allocation does not require a new address on each reconnect: DHCP leases may be reused or renewed. The new lesson avoids that claim. [DHCP](https://www.rfc-editor.org/rfc/rfc2131.html)                                                                                                                                             |
| 65           | Generic top-level domain names are described as three letters.                                                             | This is not a general length rule. The lesson uses reserved `.example` names and explicitly marks the DNS hierarchy as an educational example, not a live delegated `.example` service. [Reserved domains](https://www.rfc-editor.org/rfc/rfc2606.html)                                                                                      |
| 65           | Transit nodes in the packet diagram are labeled servers.                                                                   | Identify the packet-forwarding role as routers. A server responds to a service request; it is not a required label for every transit node. [Router functions](https://www.cisco.com/site/us/en/learn/topics/small-business/what-is-a-router.html)                                                                                            |
| 66           | Transfer speed is said not to depend on distance from the web server.                                                      | Distance affects propagation delay. Bandwidth, processing, queues, transport behavior, and server performance affect observed completion time too. The lesson separates capacity from delay. [Delay components](https://www.cisco.com/c/en/us/support/docs/voice/voice-quality/5125-delay-details.html)                                      |

## What each interaction should teach

| Lesson   | Learner intervention                                          | Observable consequence                                                       | Boundary of the model                                                                                                                                                                                                                        |
| -------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Journey  | Send a request                                                | An outbound request and returning response                                   | A few roles represent many links; no real web request or geographic route is measured.                                                                                                                                                       |
| Scale    | Select scope                                                  | A different setting and group of connected devices                           | No fixed kilometer thresholds or literal geographic scale.                                                                                                                                                                                   |
| Hardware | Rotate and separate the assembly; select a part               | The part and its role become visible                                         | Stylized home combination device, not a manufacturer's teardown. Antennas serve radio access, not IP route choice.                                                                                                                           |
| Media    | Choose copper, fiber, or radio; expose structure              | Different transmission medium and signal representation                      | Moving dots are symbols; neither literal particles nor a timing measurement.                                                                                                                                                                 |
| Routing  | Disable or restore an edge                                    | Different valid route, or no route                                           | Unweighted BFS, immediate recomputation; not an emulation of Internet routing protocols.                                                                                                                                                     |
| DNS      | Resolve each name, repeat a lookup, clear cache               | Different answer per example name; repeat query uses stored result           | Simplified synthetic hierarchy; no actual DNS request; no complete TTL expiry or DNSSEC model.                                                                                                                                               |
| Packets  | Play, pause, or step through one loss-and-reordering scenario | Out-of-order receipt, a gap, ACK, automatic recovery, ordered reconstruction | Four illustrative pieces and a fixed event sequence; not actual TCP segmentation, byte sequence numbers, full ACK/timer semantics, or congestion control.                                                                                    |
| Speed    | Change Mbps and one-way delay                                 | Serialization changes with Mbps while propagation remains independent        | One-link ideal estimate; no headers, setup, queues, loss or speed test.                                                                                                                                                                      |
| Security | Change port rule and TLS state                                | Delivery decision and content protection change independently                | Simple port filter and encryption illustration, not a real firewall/TLS stack. HTTPS does not certify honesty. [TLS](https://www.rfc-editor.org/rfc/rfc8446.html), [Chromium](https://blog.chromium.org/2023/05/an-update-on-lock-icon.html) |
| Recap    | Commit to a prediction                                        | Corrective feedback explains the cause                                       | Formative practice, not a validated assessment of mastery.                                                                                                                                                                                   |

## Content acceptance checks

- Ten slides follow a cause-and-effect sequence, each with a question, an action, a core principle, and three supporting notes.
- Main prose is Mongolian. English abbreviations are retained where they identify established protocols or units.
- References are attached to relevant slides; the original PDF is available alongside current primary technical documentation.
- No claims of a real DNS query, live network measurement, real cryptography, or engineering-accurate 3D hardware.
- Every interactive model must be checked against the observable consequence in the table above. Correct source text alone is insufficient evidence that an animation behaves correctly.

Implementation and browser verification results belong in the application's final validation report; this content review does not claim test passes before those checks run.
